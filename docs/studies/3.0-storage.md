# What TitanKeys' big data costs on the phone (3.0)

The Orchestrator, 2026-11-17: Rime's files and the swipe models are copied out of the APK on first use. How much does that
cost the phone in storage and time, and can it be avoided? Measured on the PC from main f4c835f6's Debug APK (304.5 MB as
one file, 290.4 MB as the build reports it) and the code. The phone's own timing is A's next slot.

## The copies

Every engine that opens its data by path copies it out of the APK once, checks each file's SHA-256, and keeps it under the
app's files. The APK keeps its own copy, so the data is on the phone twice: compressed in the APK, raw in the files.

| Data | Copied by | To | On disk after the copy | Still in the APK (compressed) | When |
|---|---|---|---:|---:|---|
| Rime: every Chinese input method's tables, both grammars, the next-word tables | `RimeData.install` | `files/engines/rime/shared` | **162.2 MB** | 98 MB | the first Chinese input method used, any of them |
| Engine 2.0's models (`swipe2/`) | `ModelAssets.install` | the app's files | **92.9 MB** | 74.0 MB | the swipe engine's first start, in every build |
| Mozc's dictionary | `RimeData.install` | `files/engines/mozc/shared` | 19.0 MB | 13.2 MB | Japanese's first use |
| The FUTO swipe models (`swipe/`) | `ModelAssets.install` | the app's files | 18.7 MB | 10.9 MB | the swipe engine's first start |
| **Copied in all** | | | **292.8 MB** | **196 MB** | |

- **Total footprint after first use of every language:** about **583 MB**. That's the installed APK (290 MB) plus the copies (293 MB), plus learned words and settings, which are a few MB at most.
- **For an English-only user:** about **402 MB**, the APK and the two swipe copies.
- **During an update:** Rime's and Mozc's copies go into a new folder while the old one stays, so the new data lands whole. For that moment Rime takes 324 MB, twice its data.
- **Not copied:** the word lists, autocorrect and the input methods' files are read from the APK as streams, and the native libraries run from the APK in place (stored, 16 KB aligned).

**Rime copies far more than one person uses.** It copies every Chinese input method's data, whichever is on:

| Input methods on | What they need | Copied today |
|---|---:|---:|
| Yale or Jyutping (Cantonese) | jyut6ping3 table, `tk_yue.gram`, Cantonese next words, shared files: **54 MB** | 162 MB |
| Pinyin | luna_pinyin table, Mandarin grammar, Mandarin next words: **57 MB** | 162 MB |
| Zhuyin | terra_pinyin table, Mandarin grammar: **61 MB** | 162 MB |
| Cangjie or Quick | their tables: **14 to 30 MB** | 162 MB |
| All six | 162 MB | 162 MB |

## First-use time

On this PC the copy runs at about 100 MB/s (inflate, SHA-256 and write, one thread):
- Rime: 162 MB in 1.6 s;
- engine 2.0's models: 93 MB in 1.0 s;
- Mozc: 19 MB in 0.2 s.

The phone is likely 2 to 4 times slower at this, so the first Chinese key after an install waits about **3 to 6 s** while Rime's data is copied. That's an estimate for A to time.

A's check:
1. A fresh install of the Debug build.
2. Yale on.
3. The first key typed.
4. In `adb logcat -s TitanKeysIM`, the line "Input method yue-yale loaded in … ms".

## Ways to avoid it

1. **Copy only the input methods that are on (recommended, no native change).**
   - How: data.sh writes which files each schema needs beside `rime.sha256`. `RimeData` copies the shared files plus the schemas of the input methods that are on, and adds a schema's files when its input method is turned on.
   - Saves: a Cantonese-only user copies 54 MB, not 162 MB (108 MB less on the phone), and the first Chinese key waits a third as long.
   - Cost: the APK doesn't change. Code: data.sh, `RimeData`, `RimeEngine.start`, and their checks.
   - Risk: Rime must open a schema whose neighbours' files are missing. It does: it opens each schema's dictionary only when that schema is selected, but that's to be checked on the PC first.
2. **Read Rime's and Mozc's data in place in the APK.**
   - How: the files stored uncompressed (`noCompress`), and librime and Mozc reading them through the APK's file descriptor at the entry's offset.
   - librime opens every table by path (`MappedFile`), so this means patching librime, a third-party library, to take an fd and an offset. Mozc can take its data as a memory block (`DataManager` from an array), so it needs only our `tk_core` to map the APK region.
   - Saves: 181 MB on the phone.
   - Cost: the APK grows by about 70 MB, the data stored raw instead of compressed. Play's download compresses it again, so that stays about the same.
   - Not simple: a librime patch to carry and keep rebuilding.
3. **Engine 2.0's models (93 MB):** ONNX Runtime can open a model from a memory-mapped buffer of an uncompressed asset, which would save the copy.
   - Engine 2.0 isn't mine to change ("never change engine 2.0 or the swipe models"), so this is for the swipe engine's owner.
4. **The update's double:** copying file by file, each checked and swapped in turn, would keep the peak at the data's size plus one file, instead of twice the data.

## Recommendation

Do 1 now: no native change, the biggest saving for the people who use one or two Chinese input methods, and a faster first
key. Leave 2 unless storage becomes a complaint. Hand 3 to engine 2.0's owner.
